# M10c — Clarity: build plan

**Date:** 2026-10-15 · **Branch:** `m10c-clarity` (from `m10b-haptics` at 4c82e54) · **Version:** 0.5.0, versionCode 5

## Plain summary

The owner kept the Ink Panel look (the redesign canvas was turned down) and asked for the review's improvements instead:
make each screen say what to do next, quieten what's finished, and make the common things quicker. Everything here is
in the app; nothing changes on the server. Three larger pieces come with it: clearing a simple quest from Today with a
hold, workouts that remember last time and time your rest, and a home-screen widget. The widget is a new native module,
so it needs one new development build (EAS free tier) for the emulator checks; the pilot APK waits for the owner's yes.

## Decisions

1. **No server change, no migration, no deploy.** Every item reads what the state already sends. One server-side
   tidy-up is noted for later (item 7).
2. **"Today counts" is the rules' own test.** `isStreakDay` (core quest done, or any two quests) on today's quests,
   the same test `quest/cleared.ts`, the Chronicle's `todayMark` and the server's closing use. When it holds and no
   check-in is waiting, the streak shows one more than the server's count, with "today counts". The server adds that day
   when it closes, and the shown number stays the same, so the M10b tick plays once, when it first grows.
3. **The day's options fold into one row**, "Change today", closed by default. The confirm panels inside are unchanged.
4. **A rest today is offered only while today doesn't count yet.** Today the server accepts a rest on a day that
   already counts and spends one of the two rests in seven on it. The phone stops offering it then (Rest tomorrow
   stays). Making the server refuse it too would need a deploy: later.
5. **Two new kit pieces:** `RowLink` (a row that opens another screen: label, an optional value line, a chevron) and
   `LinkButton` (a quiet text action, at least 48 dp). Buttons stay for actions; screens are reached by rows.
6. **Quick clear**: only check-off quests (completion `tap`) that aren't sealed by the Trial, outside the reading slot,
   get a "Hold to clear" bar under their card on Today (the existing `HoldButton`, 0.8 s). It sends the same
   `complete` event as the quest screen. With a screen reader on, the bar becomes Clear → Confirm (HoldButton's own
   path). Rating stays optional, on the quest screen.
7. **Workout memory is kept on the phone** (`lmu.lastSets`, like the portrait choice): each exercise's reps from the
   last logged workout, and each rep-log quest's last sets. A workout starts each set at last time's number when it
   lies in the exercise's current range, else at the bottom of the range (M6c decision 9); a "Last time" line shows the
   numbers. Removed with the character. A restored character on a new phone starts without it.
8. **The rest timer is in the app only**: a "Done" check on each set row starts a 2-minute rest (the content's own
   "Rest about 2 minutes between sets"), counted from timestamps, so it survives the screen going off. "+15 s" and
   "Skip"; at zero a click (`stamp`) and "Rest over". The checks don't change what's logged: Log still sends every set.
   No notification (keep it simple; timer alerts stay as M7d made them).
9. **The widget: `react-native-android-widget` 0.22.1** (peer `expo >=54`; Expo's own `expo-widgets` is iOS-only). One
   "Today" widget, 4×2 cells: the day and the streak, the core quest (or "Day cleared"), how many quests are cleared,
   and a tap that opens the app. The app writes a small snapshot to the phone's key-value store (`lmu.widget`) and asks
   for a redraw when it changes; the widget's own task draws from that snapshot (when added, resized, and every 30
   minutes). After the day's end it says a new day is ready. The character's deletion clears it. Only `src/widget/`
   imports the library. A custom entry (`index.ts`: `expo-router/entry`, then the widget's task) is needed.
10. **Version 0.5.0, versionCode 5.**

## Work, in order (each step: change → test → typecheck)

### 1. Helpers (`src/game/today.ts`, test `test/today.test.ts`)
- `todayCounts(view)`: today is open, no check-in waiting, `isStreakDay` holds on today's quests.
- `shownStreak(view)`: `{ current, best }` with today added when it counts.
- `dayCleared(today)`: every quest of the day cleared.
- `nextQuest(today)`: the first open quest in slot order (recovery, core, sides, reading), for the "Next" chip.
- `quickClearable(quest, hold)`: completion `tap`, open, not sealed, not the reading slot.

### 2. Kit (`src/ui/RowLink.tsx`, `src/ui/LinkButton.tsx`, tests in `test/ui.test.tsx`)
- `RowLink`: label, optional value line, chevron; min 56 dp; `accessibilityRole="button"`; wraps at the largest font.
- `LinkButton`: underlined bold text, ember or chalk, min 48 dp.

### 3. Today (`Today.tsx`, `QuestCard.tsx`, `DayActions.tsx`)
- **Header:** the day number drops from Display to Title size under the date; "Next: Lv n" goes (the XP line
  stays); shields show as the icon and number (its label still says "n of 2 shields"); the streak shows
  `shownStreak` with "today counts" when it does.
- **Core quest card, open:** a seal-red "BEGIN" bar at the card's foot (part of the card's one pressable; its
  label ends "Begin").
- **Cleared quests:** the core quest becomes a slim paper row (title, "Cleared +10", time) instead of the poster;
  every cleared row's stamp becomes a small ember line, so finished things are quiet.
- **Next:** with the core quest cleared, the next open quest carries a "Next" chip.
- **Day cleared:** when every quest is cleared, a panel heads the list: "Day n cleared", the XP earned today, and when
  the next day starts.
- **Notices:** one at a time with "Got it" and "1 of n".
- **Change today:** one row that opens the day's options in place.
- **Rest:** decision 4 (`DayActions.canRest` and the rest panel).

### 4. Settings (`Settings.tsx`, content `settings.ts`)
- Rows (`RowLink`) for Daily plan, Training, the Pact, Notifications, Your data and privacy, Developer.
- "Voice, rhythm and minutes" becomes **"Daily plan"**, with its values as the row's line (voice · day ends · minutes).
- **Delete my character** moves to the end, under its own "Your character" heading, after About.

### 5. Character (`Character.tsx`, `character/StatsPanel.tsx`)
- "Switch portrait" becomes a round icon button on the portrait's corner (48 dp, labelled).
- Stats: the rank as a small "Rank E" line beside the points, not a stamp; the lead line goes (each bar's own line
  says what it measures).
- Class change becomes a `RowLink` ("Class · Warrior", the lock line under it).

### 6. Chronicle (`Chronicle.tsx`)
- The tiles use `shownStreak`.
- Growth: the summary line first; only stats that grew; none grew yet → just the line.

### 7. Quest cleared (`quest/Cleared.tsx`)
- "Logged by mistake? Undo" becomes a `LinkButton`.

### 8. Quick clear (`Today.tsx`, `QuestCard.tsx`)
- Decision 6. Clearing plays the row's stamp and the `stamp` click (the Thud on the cleared row, as the Quest screen's).

### 9. Workout memory and rest (`quest/WorkoutLog.tsx`, `quest/RepLog.tsx`, `quest/rest.ts`, `quest/lastSets.ts`, store)
- Decisions 7–8. The store keeps `lastSets` (read at start, written after a workout or rep log is logged, removed on
  delete). Pure helpers tested: `startFromLast`, `restLeft`.

### 10. Widget (`src/widget/`, `index.ts`, `app.json`, `assets/widget/preview.png`)
- Decision 9. `widgetSnapshot(view, now)` is pure and tested; `TodayWidget` renders it (tested with the library
  mocked); the store's subscriber writes the snapshot and requests a redraw only when it changed; the delete clears it.
- The Jest setup mocks the library, as it does `expo-haptics`; a test pins that only `src/widget/` imports it.

### 11. Version, docs, checks
- 0.5.0 / 5. README, CLAUDE.md (the widget module), the roadmap row 10c, the visual spec note, the checklist's M10c
  section, and an "As built" here.
- `npm test` (app, content, rules, server unit), the typecheck, `check:functions`, `check:portable`, `check:bundle`.

### 12. The emulator (the new development build)
- `npx eas-cli@latest build --platform android --profile development` (free tier), installed over `6fa0bb39`
  (Vera kept). Production bundle through Metro for timing rows.
- Rows (each read with uiautomator and screenshots):
  1. Today's header: the smaller day, no "Next: Lv", shields as icon and number.
  2. An open core quest shows BEGIN; tapping it opens the quest.
  3. Clearing the core quest: the card becomes a slim row; the streak shows one more with "today counts", and ticks once.
  4. The next open quest shows "Next".
  5. All cleared: the Day cleared panel; the stamps are quiet.
  6. Change today opens and closes; swap, hard day and rest behave as before; on a counted day, Rest offers only
     tomorrow.
  7. A check-off side quest cleared by a hold; a tap alone does nothing; TalkBack's tap path (if practical).
  8. A workout or rep log: "Done" starts the 2-minute rest; +15 s and Skip; the click at zero; the next time the reps
     start from last time.
  9. Settings: rows, Daily plan's line, Delete at the end; at font 2.0 nothing is cut off.
  10. Character: the portrait button switches; ranks as lines; the class row.
  11. Chronicle: tiles match Today; growth hides zeros.
  12. Quest cleared: Undo as a link, still undoes.
  13. The widget: added from the launcher; shows the day, streak, core quest and count; updates after a quest is
      cleared; opens the app; says "new day" after the day ends; blank after the character is deleted (checked on a
      throwaway character, never Vera's).
  14. Reduced motion: nothing new moves.
- The pilot APK (preview) only with the owner's yes.

## Not in M10c
- The server refusing a rest on a counted day (decision 4); a notification when the rest ends; last sets kept on the
  server; more than one widget size; an iOS widget.
